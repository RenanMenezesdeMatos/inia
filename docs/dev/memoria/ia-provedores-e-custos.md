### AI Providers, Modelos, Roteamento e Custos V1 (2026-09-22, migration 076)

Regra: **a regra de negócio pede uma FUNÇÃO (Use Case), nunca um modelo; o MESMO roteador resolve Use Case → policy da organização → conexão → modelo → adapter.** Nenhum roteador paralelo: `llm-gateway.ts › generateForRoute` consulta a porta `AiRuntime` (`model-routing/ai-runtime.ts`) ANTES do caminho legado — policy ACTIVE da organização para o Use Case; sem policy = perfis por tier + `GEMINI_API_KEY` exatamente como antes (migration não insere linha nem copia segredo de ENV → ZERO troca silenciosa). O runtime só é registrado no servidor real (`createApp(pool, { registerAiRuntime: true })`); testes/scripts de benchmark ficam byte a byte no legado. Organização da chamada = sessão (`requireAuth` → `runWithAiOrganization`) ou matrícula do Workflow (`engine.ts`); sem organização = legado (não existe "organização padrão"). ADR-008 + `docs/dev/ai-providers.md` + Wiki `/wiki/administracao/ia-modelos`; tela `Administração › IA / Modelos` (`/admin/ai`).

- **Provider ≠ Conexão ≠ Modelo**: Provider = catálogo em código (`ai-management/domain/ai-provider-catalog.ts`, só existe com adapter; UI montada pela metadata); adapters POR PROTOCOLO (`GOOGLE_GENAI`, `OPENAI_CHAT_COMPLETIONS` — OpenAI/xAI/LM Studio/Ollama/compatível —, `ANTHROPIC_MESSAGES`; `infrastructure/adapters/`, nunca repetem request; `http.ts` = timeout + categoria + redação). Conexão/modelo/preço/policy/uso/orçamento = dados da organização (`ai_connections`, `ai_connection_secrets`, `ai_models`, `ai_model_pricing`, `ai_routing_policies`+`_models`, `ai_usage_events`, `ai_budgets`).
- **Use Cases** (`model-routing/ai-use-cases.ts`, derivados da auditoria dos pontos reais): INVESTIGATION_PLANNING (Tools), SEMANTIC_EXTRACTION / PATTERN_SYNTHESIS / OUTCOME_ATTRIBUTION (distinguidos pela tag `stage:*` que `interaction-tools.ts › askModel` passou a enviar na classificação), AGENT_RESPONSE, SPECIALIST_RESPONSE, ORCHESTRATOR_ROUTING (Tools), ORCHESTRATOR_SYNTHESIS, MANAGERIAL_SYNTHESIS, CHAT, VOICE_REALTIME (não roteável), MODEL_TEST (interno). Capacidade ausente/não declarada = inelegível; origem DISCOVERED | MANUAL | INFERRED (manual nunca é sobrescrita por sincronização).
- **Policy** (DRAFT → ACTIVE → ARCHIVED; só rascunho válido ativa; "Testar roteamento" = mesmo plano, zero chamada): PINNED (1 modelo), FALLBACK_CHAIN (2–5), AUTO determinístico (COST_FIRST preço vigente · LATENCY_FIRST mediana real 7 dias · BALANCED · QUALITY_FIRST = tier DECLARADO pelo admin, sem número mágico). Fallback só em RATE_LIMIT/TIMEOUT/NETWORK/PROVIDER_ERROR/MODEL_UNAVAILABLE (AUTH só opt-in; INVALID_REQUEST/CONTEXT_LIMIT nunca); tentativas com o mesmo `correlation_id`; policy sem candidato = `AI_ROUTE_UNAVAILABLE` (nunca cai no legado em silêncio); rate limit < 60 s vai para o fim da fila.
- **Segredo**: AES-256-GCM da Central de Dados (mesma função/chave `DATA_HUB_SECRET_KEY`); API devolve só `configured` + máscara; não há rota de leitura; logs com `redactSecrets`; o gateway tira `details.body` cru dos erros legados. Endpoint: http(s), sem credencial na URL, sem 169.254.x; "localhost" = servidor da INIA.
- **Uso/custo/orçamento**: um evento por tentativa (sem prompt/resposta); tokens informados ou null; custo = uso × preço vigente em ponto fixo (`domain/decimal.ts`, BigInt escala 12; `numeric` no banco) com `pricing_id` (preço novo FECHA o anterior); `cost_status` ESTIMATED | UNKNOWN (EXACT reservado); local zerado = "custo de API 0 · computação não medida"; sem FX. Orçamento GLOBAL/USE_CASE/PROVIDER com moeda, limiares 70/90/100 no Sino (`AI_BUDGET_THRESHOLD` → target `ADMIN_AI_USAGE`) e hard limit (`AI_BUDGET_EXCEEDED`, evento BLOCKED; cache de gasto 15 s). Dashboard por agregação SQL (provider/modelo/Use Case/dia, custo por moeda). Saúde = último teste + telemetria 24 h, sem polling.
- **Permissões** derivadas de papel + escopo existentes: admin global = AI_CONFIG_READ/WRITE, AI_SECRETS_WRITE, AI_USAGE_READ, AI_BUDGET_WRITE; admin de grupo = só leitura. Tudo filtrado pela organização da sessão (id de outra org = 404). Auditoria em `audit_logs` sem segredo.
- **Fechamento operacional (2026-09-22)**: nenhuma chamada sai sem evento de uso — propósito sem mapeamento vira o Use Case interno `UNCLASSIFIED` (não roteável, orçamento global vale); prova estrutural `model-routing/ai-call-sites.test.ts` (só os clientes conhecidos têm endereço de provider; clientes crus só importados por quem os embrulha) + "zero spend sem uso" em `ai-runtime-gateway.test.ts`. Exceções documentadas: voz Live, scripts de benchmark (sem runtime), falha ao gravar o evento. Uso LEGADO é precificado pela tabela da organização quando o mesmo provider + id do modelo está cadastrado (ambíguo = sem preço) — só contabilidade. Gemini informa raciocínio fora da saída → `reasoningPerMillion = output`. Áudio e armazenamento de cache por hora = componentes não modelados. Dev: conexão Gemini real (criada pelo admin), modelos `gemini-3.1-flash-lite`/`gemini-3.8-flash` com preço oficial (3.8: promocional até 31/12/2026 + versão 2027) e Ollama local `qwen3:8b` (contexto do servidor 4.096 ≠ 40.960 do modelo — `OLLAMA_CONTEXT_LENGTH`); ZERO policy ativa. Ver `docs/dev/ai-providers.md`.
- Bypasses antigos agora pelo gateway: chat sem Orquestrador (`createChatStreamer`, policy CHAT ou stream legado com uso lido do SSE) e voz (`createVoiceSessionStarter`: hard limit antes da sessão + sessão registrada sem tokens).
- Provas: `ai-management/domain/*.test.ts`, `infrastructure/adapters/adapters.test.ts` (fetch falso), `model-routing/ai-runtime-gateway.test.ts`, `INIA_DB_PROOF=1 npx vitest run ai-providers-proof` (servidor compatível com OpenAI falso em 127.0.0.1 — `testing/fake-openai-compatible-server.ts`; QA manual: `npx tsx scripts/dev/fake-ai-provider.ts`). Zero API paga na suíte. Futuro JEV/TypeSafe: só `docs/dev/jev-typesafe-checkpoint.md` + `AiModelKind` reservando EMBEDDING/CLASSIFICATION/DECISION.

### Feedback por outro provedor — FEEDBACK_WRITER roteável (2026-10-08)

Regra: **o feedback não depende do Gemini — depende das policies `FEEDBACK_ANALYSIS` + `FEEDBACK_WRITER` da organização; sem elas, as rotas fixas de sempre, sem mudar um byte.** Motivo: POC num cliente que só libera OpenAI. `FEEDBACK_WRITER` ("Redação e verificação do feedback") passou a `routable: true`; UMA policy atende redação/verificação/coerência do motor, redatores do feedback confiável, narrativas (supervisor, fechamento) e verificação semântica da narrativa, e o redator por interação.
- O caminho por policy ignorava schema/teto/tempo da etapa (valia para todo Use Case): agora `generateForRoute` passa `responseSchema`, `maxOutputTokens` e `transport.timeoutMs` em `PolicyExecutionRequest`; o runtime aplica teto = min(etapa, modelo cadastrado) e tempo = max(etapa, modelo/conexão) (`effectiveMaxOutputTokens`/`effectiveTimeoutMs` em `ai-runtime-service.ts`); `retries: 0` continua impedindo o limitador de repetir.
- Adapter OpenAI: schema → `json_schema` com `strict: false` (`toJsonSchema` converte o dialeto do Gemini: maiúsculas, `nullable`, `propertyOrdering`); sem schema → `json_object` (todos os prompts estruturados têm "JSON"); provider `OPENAI` manda `max_completion_tokens`, os demais `max_tokens`; `finish_reason` → STOP/MAX_TOKENS/SAFETY. Google: `generationConfig.responseSchema` como o legado. Anthropic ignora o schema.
- `WriterProvenance.route` + `provider`/`requestedModel` da policy quando roteado (falha antes da resposta não traz rota).
- Não validado: qualidade do motor com modelo OpenAI (zero chamada paga), Azure OpenAI (caminho provável: conexão OpenAI com endpoint `/openai/v1`), servidores compatíveis com `json_schema`.
- Voz (Live no navegador, recado e "Ouvir com a INIA") continua Gemini — opções A–D com custo em `docs/dev/ai-providers.md` ("O que continua exigindo Gemini"); nada implementado.
- Provas: `feedback-engine/infrastructure/gateway-engine-model.test.ts` (legado byte a byte, 503 = 1 chamada, policy recebe schema/teto/tempo), `adapters.test.ts`, `ai-runtime-service.test.ts`, `INIA_DB_PROOF=1 NODE_ENV=test npx vitest run feedback-writer-policy-proof` (7/7 em 08/10; controle negativo com `routable: false` falha em `AI_USE_CASE_NOT_ROUTABLE`). Provas de banco de IA usam a mesma organização: rodar uma por vez.

### Voz do recado por policy — SPEECH_SYNTHESIS roteável (2026-10-08)

Regra: **a voz do recado e do "Ouvir com a INIA" segue a policy "Voz do recado do avatar" da organização; sem ela, a composição de sempre (Live do Gemini conferido + TTS de reserva), sem mudar um byte.** A conversa por voz (Live no navegador) continua fora do roteamento — com a policy, recado e conversa podem ter vozes diferentes.
- Voz no MODELO (`ai_models.metadata.speech = { voice, instructions }`, sem migration; a sincronização preserva), editável em Modelos › Configurar (campos aparecem com a capacidade Áudio). Elegibilidade (`ineligibilityReason`, `requiresSpeechVoice` no Use Case): AUDIO declarado + adapter em `SPEECH_SYNTHESIS_ADAPTERS` (Chat Completions) + voz.
- Porta: `AiProviderAdapter.synthesizeSpeech?` (OpenAI: `/audio/speech`, `response_format: "pcm"`, 24 kHz fixo, instrução só se cadastrada); runtime `speechIdentityWithPolicy?`/`synthesizeSpeechWithPolicy?` (opcionais); gateway `createRoutedSpeechSynthesizer(legacy)` + `speechCacheIdentity(legacy)`; routers recebem `{ synthesize, accepted() }`.
- Cache: identidade calculada por pedido — policy = voz do primário + `providerModelId#hash12(instrução)` (`speechCacheModelKey`); trocar voz/modelo/tom/policy regenera; policy sem candidato = identidade vazia (nunca serve áudio antigo).
- Custo UNKNOWN (resposta binária sem tokens; SSE com uso não usado — formato não documentado na referência). "Testar modelo" num modelo com voz sintetiza uma frase.
- Não validado com chave real: voz PT-BR, números/protocolos, tom. Provas: `speech-synthesis-policy-proof` (6/6, controle negativo falha 4/6), `speech-routing-gateway.test.ts`, `ai-speech.test.ts`, `adapters.test.ts`, `ai-routing-policy.test.ts`, `ai-management.test.tsx`.

### Quem mais usa — ranking de uso de IA por estrutura (2026-10-15, migration 143)

Regra: **cada evento de uso vai para UMA pessoa por fato gravado, e a pessoa vai para a unidade do nível pela estrutura atual; o que não chega a ninguém é a linha "Sem vínculo", nunca atribuído nem escondido.** Tela: `Administração › IA / Modelos › Quem mais usa` (`/admin/ai?tab=ranking&level=<nível>&sort=<ordem>` — só códigos na URL).
- **Atribuição** (`ai-management/domain/ai-usage-ranking.ts`): `WORKFLOW` = `enrollment_id` → colaborador da matrícula (`scheduled_subject_id` ∨ `interactions.operator_id` ∨ medição `PERSON`), mesmo que alguém logado tenha disparado (ex.: "Executar agora"); `REQUEST` = `ai_usage_events.requester_person_id` (NOVA, 143, sem FK, nula fora de request); `OTHER` = nenhum dos dois. A pessoa da sessão entra pelo MESMO contexto assíncrono da organização: `require-auth.ts` → `runWithAiOrganization(..., { requesterPersonId })` → `currentAiRequesterPersonId()` → `persist` (e o "Testar modelo" grava `actor.personId`). O motor de Workflow abre contexto próprio sem pessoa (provado em `ai-usage-correlation.test.ts`). Eventos anteriores a 15/10/2026 não têm a pessoa: pedidos antigos = "Sem vínculo / sem pessoa identificada".
- **Níveis** (os seis pedidos; Coordenador fica fora): Diretoria/Gerência Sênior/Gerência/Supervisor = líder mais próximo com o cargo subindo por `reports_to_id` (a própria pessoa conta; CTE recursiva que para ao achar, anticiclo 32); Grupo/Subgrupo = `team_id`/`subteam_id` do cadastro. Cada linha soma a pessoa e toda a estrutura abaixo. Motivos do "Sem vínculo": `NO_PERSON`, `WORKFLOW_WITHOUT_PERSON` (matrícula sem colaborador ou apagada), `OUTSIDE_LEVEL` (pessoa do escopo sem aquele nível acima/no cadastro).
- **Segurança**: permissão NOVA `ai.usage_ranking.view` (ADMINISTRADOR_GERAL e ADMINISTRADOR; nunca derivada de `ai.manage`/`ai.view`) → `AI_USAGE_RANKING_READ` em `/admin/ai/me` só com ela + `AI_USAGE_READ`. Recorte = `scopedPeopleSql` da MESMA permissão (organização/Grupo/Subgrupo/Minha estrutura), lido do banco a cada request, pessoa da conta (`request.access.personId`, não o JWT). Escopo restrito: só pessoas do escopo entram; cada linha soma só elas (a Diretoria aparece com o número do escopo); uso sem pessoa só para quem tem organização inteira e sem filtro de Grupo/Subgrupo. Nome de líder de ramo onde há pessoa do escopo aparece (organograma é aberto na organização); ramo sem ninguém do escopo não gera linha. Filtros zod `.strict()` (sem texto livre: `search` = 400), Grupo/Subgrupo só estreitam; período personalizado ≤ 1 ano (o mesmo `resolvePeriod` do painel).
- **Consulta** (`application/ai-usage-ranking-service.ts`): UMA instrução — bruto do período reduzido por chave matrícula × pessoa antes das junções; ranking = agregado por unidade (limitado ao número de unidades, nunca ao histórico), página por posição (`row_number` + LIMIT/OFFSET sobre o agregado, `total` = unidades), nomes só das unidades ranqueadas, custos só da página/"Sem vínculo". Dev (1,2 mil eventos/30 dias): 5–12 ms. "Sem vínculo" e "Total do recorte" vêm fora da paginação (em toda página).
- **Frontend**: `components/admin/ai/usage-ranking-tab.tsx` + `usage-ranking/ranking-views.tsx` (tabela com linha fixa "Sem vínculo" e total; cards), `schemas/admin/ai-usage-ranking.schema.ts`, `services/admin/ai-usage-ranking-service.ts`, `queries/admin/use-ai-usage-ranking-queries.ts` (keys sob `adminQueryKeys.ai()`). Aba some sem `AI_USAGE_RANKING_READ`.
- Provas: `INIA_DB_PROOF=1 NODE_ENV=test npx vitest run ai-usage-ranking-proof` (organização PRÓPRIA; 9/9 em 15/10: seis visões, paginação, ordenação, filtros, escopo Grupo/Subgrupo sem nome/id de fora, contexto, 403 e 400, e request autenticado → `requester_person_id` no banco), `domain/ai-usage-ranking.test.ts`, `ai-routing-policy.test.ts`, `ai-usage-correlation.test.ts`, frontend `usage-ranking-tab.test.tsx`. Wiki: `/wiki/administracao/ia-modelos#quem-mais-usa`.
- Limitações: estrutura ATUAL (quem mudou de equipe leva o uso antigo; não há "estrutura no fato"); sem limiar de privacidade para unidade pequena (Supervisor com 1 operador mostra o uso dele); medição de Grupo/Subgrupo (subject TEAM) e execução consolidada sem colaborador caem em "Sem vínculo"; volume grande (centenas de milhares de eventos no período) agrega o bruto a cada request — caminho: resumo diário por chave de atribuição, como `ai_usage_daily`.

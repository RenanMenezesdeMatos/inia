Estilos inline são exigidos por React Flow, Radix, motion, recharts e pela prévia DOCX, e um nonce em `style-src` desligaria o `'unsafe-inline'` dos atributos `style`. No Chromium, `<script>` inline criado via DOM por código já confiável roda mesmo sem nonce (verificado); hoje o bundle só cria scripts no carregador de chunks, no pré-carregamento do React e no `__next_s` do próprio Next, nunca a partir de dado | Não introduzir código que monte `<script>` a partir de dado; ao revisar a UI, avaliar `style-src-elem` com nonce mantendo `style-src-attr 'unsafe-inline'` (exige que toda biblioteca que injeta `<style>` aceite o nonce); opcional: endpoint `report-to` para receber violações em produção |

## Validações que não puderam ser executadas aqui

- Conexão real a SQL Server/PostgreSQL/MySQL externos com a política de destinos (a prova `external-database-proof` exige os
  contêineres de exemplo; não foi executada).
- Sessão de voz com microfone e Gemini Live real (efeito do teto de sessões de voz e da CSP no WebSocket).
- Instalação Windows/IIS (cabeçalho `X-Forwarded-For` do ARR e `TRUST_PROXY=loopback` no servidor real).
